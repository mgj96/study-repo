# 유형 훈련 — 격자 BFS/DFS (섬 개수 · 최단 거리)

> 백로그 1번 — **기업 2번 문제 최다 빈출인데 드릴이 없던 유형**.
> **난이도**: 프로그래머스 **Lv2** · HackerRank Medium · 기업 2번(중) — 미로·지도·전염 확산·게임 맵이 전부 이 유형의 옷만 바꾼 것.
> 진행: **🤔 생각 → 📖 읽기 → ✅ 확인** 순서.

---

## 0단계. 판별 — 지문 신호

격자(2차원 배열) + 아래 문구가 보이면 이 유형이다:

| 지문 신호 | 알고리즘 | 이유 |
|---|---|---|
| "**몇 개의 덩어리/구역/섬**인가" | DFS 또는 BFS (아무거나) | 연결된 것 전부 방문 표시만 하면 됨 (flood fill) |
| "**최단 거리 / 최소 이동 횟수**" | **BFS 고정** | 아래 1단계 — DFS로 하면 틀린다 |
| "칸마다 이동 **비용이 다르다**" | 다익스트라 (3번 급) | BFS는 비용 균일일 때만 최단 — 여기선 신호만 알면 됨 |
| "모든 경로/경우의 수를 세라" | DFS+백트래킹 | 탐색이 아니라 열거 문제 |

> 판별 핵심 한 줄: **세는 문제는 아무거나, 최단은 BFS, 비용 다르면 여기가 아니다.**

## 1단계. 🤔 생각 — "최단"이면 왜 DFS가 안 되나?

*(DFS도 결국 도착점에 도달하는데, 왜 최단 거리는 못 구하나?)*

<details><summary>📖 추론 열기</summary>

DFS는 **한 방향으로 끝까지** 파고든다 — 처음 도착한 경로는 "아무 경로"지 최단이 아니다. 모든 경로를 다 뒤져 최솟값을 갱신하면 되긴 하지만 지수 시간이다.

BFS는 **거리 순서대로** 퍼진다: 시작점에서 거리 1인 칸을 전부 → 거리 2를 전부 → … 그러므로 —

> **BFS에서 어떤 칸에 처음 도달한 순간, 그 거리가 곧 최단 거리다.** 증명이 큐의 성질에서 공짜로 나온다: 큐에는 항상 "거리 d와 d+1인 칸들만" 순서대로 들어 있다.

이게 "최단 = BFS 고정"의 이유이고, 가중치가 붙는 순간 이 증명이 깨지므로(가까운 칸이 더 비쌀 수 있음) 다익스트라로 넘어가는 것이다.

</details>

**✅ 확인**: "BFS는 왜 처음 도달 = 최단인가?"를 큐 그림 없이 한 문장으로 말해보기 — "거리 순서대로 방문하니까"가 나오면 통과.

## 2단계. 🤔 생각 — 방문 체크는 큐에서 꺼낼 때? 넣을 때?

*(visited 표시 위치가 두 군데 가능하다. 어느 쪽이어야 하고, 틀리면 무슨 일이 나나?)*

<details><summary>📖 추론 열기</summary>

**넣을 때(offer 직전) 표시해야 한다.** 꺼낼 때 표시하면 — 같은 칸이 방문 표시되기 전에 **여러 이웃이 그 칸을 중복으로 큐에 넣는다.** 답은 맞지만 큐가 수십 배로 부풀어 **시간 초과의 단골 원인**이 된다 (격자가 크면 치명적).

> 불변식으로 기억: **"큐 안에 같은 칸은 절대 두 번 없다"** — 이 불변식은 넣을 때 표시해야만 유지된다. ([슬라이딩 윈도우 드릴](longest-unique-substring.md)의 "창 안엔 중복 없음"과 같은 사고 — 자료구조의 불변식을 정하고 매 턴 복구한다.)

</details>

**✅ 확인**: 3×3 전부 빈 격자에서 중앙 시작 BFS를 손으로 — 꺼낼 때 표시 방식이면 모서리 칸이 큐에 2번 들어가는 걸 직접 목격할 것.

## 3단계. 결론 — 템플릿 2벌 (Java)

### ① 섬 개수 (flood fill — DFS판)

```java
static int[][] g; static boolean[][] vis; static int n, m;
static final int[] dr = {-1, 1, 0, 0}, dc = {0, 0, -1, 1};   // 상하좌우 (대각선이면 8방향)

static int countIslands() {
    int count = 0;
    for (int r = 0; r < n; r++)
        for (int c = 0; c < m; c++)
            if (g[r][c] == 1 && !vis[r][c]) { dfs(r, c); count++; }  // 새 덩어리 발견
    return count;
}
static void dfs(int r, int c) {
    vis[r][c] = true;
    for (int d = 0; d < 4; d++) {
        int nr = r + dr[d], nc = c + dc[d];
        if (nr >= 0 && nr < n && nc >= 0 && nc < m && g[nr][nc] == 1 && !vis[nr][nc])
            dfs(nr, nc);
    }
}
```

### ② 최단 거리 (BFS판 — dist 배열이 visited 겸용)

```java
static int bfs(int sr, int sc, int tr, int tc) {
    int[][] dist = new int[n][m];
    for (int[] row : dist) Arrays.fill(row, -1);      // -1 = 미방문
    ArrayDeque<int[]> q = new ArrayDeque<>();
    dist[sr][sc] = 0; q.offer(new int[]{sr, sc});     // ★ 넣을 때 표시 (2단계)
    while (!q.isEmpty()) {
        int[] cur = q.poll();
        for (int d = 0; d < 4; d++) {
            int nr = cur[0] + dr[d], nc = cur[1] + dc[d];
            if (nr >= 0 && nr < n && nc >= 0 && nc < m
                    && g[nr][nc] != WALL && dist[nr][nc] == -1) {
                dist[nr][nc] = dist[cur[0]][cur[1]] + 1;
                q.offer(new int[]{nr, nc});
            }
        }
    }
    return dist[tr][tc];                              // -1이면 도달 불가
}
```

`dr/dc` 방향 배열이 이 유형 전체의 관용구다 — if문 4개 복붙 대신 루프 하나.

## 4단계. ✅ 전체 확인 — 손 추적

격자 `(1=땅, 0=바다)`:

```
1 1 0        섬 개수: (0,0)에서 DFS → (0,1)까지 방문 = 덩어리 1
0 0 1        (1,2)에서 DFS → (2,2)까지 방문 = 덩어리 2
0 1 1        답: 2
```

최단 거리(전부 이동 가능, (0,0)→(2,2)): BFS 레벨 확산 `0→1→2→3→4` — 거리 4 (맨해튼 거리와 일치하는지로 검산).

## 5단계. 함정 체크리스트

- [ ] **방문 표시는 큐에 넣을 때** (꺼낼 때 표시 = 시간 초과 1순위 원인)
- [ ] **재귀 DFS 스택오버플로** — 격자가 크면(10⁵칸+) 땅이 한 덩어리일 때 재귀 깊이 폭발 → 명시적 `ArrayDeque` 스택 또는 BFS로 전환
- [ ] 경계 검사 4개(`nr>=0 && nr<n && nc>=0 && nc<m`)를 **이웃 계산 직후 즉시** — 배열 접근보다 먼저
- [ ] (row, col) 순서 — 입력이 (x,y)로 주어져도 내부에선 `g[행][열]`로 통일하고 변환 지점을 한 곳으로
- [ ] **대각선 포함 여부** 지문 확인 — 방향 배열만 8개로 교체
- [ ] 시작점이 여러 개인 변형(전염 확산·불) — 전부 큐에 넣고 시작하는 **멀티소스 BFS** (같은 템플릿)

## 3단 요약 (암기)

- **① 결론 · WHAT** — 격자 문제는 두 질문으로 갈린다: **덩어리 세기 = flood fill(DFS/BFS 아무거나), 최단 거리 = BFS 고정.** 방향 배열 `dr/dc` + "넣을 때 방문 표시"가 템플릿의 전부다.
- **② 원리 · HOW** — BFS는 큐 성질상 **거리 순서대로** 방문하므로 첫 도달이 곧 최단이다(가중치 균일일 때만 — 깨지면 다익스트라). 방문 표시를 넣을 때 하는 이유는 "큐 안에 같은 칸 없음" 불변식 — 어기면 답은 맞아도 큐 폭발로 시간 초과.
- **③ 확장 · TRADE-OFF** — DFS 재귀는 짧지만 큰 격자에서 스택오버플로 위험(명시적 스택/BFS로 회피), BFS는 큐 메모리를 먹는다. 변형 감각: 시작점 여러 개면 멀티소스 BFS, 상태가 (위치+열쇠소지) 같은 복합이면 방문 배열 차원을 늘린다 — 템플릿은 같고 **"상태가 무엇인가"만 다시 정의**하면 된다.
