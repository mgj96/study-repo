# 유형 훈련 — DP 테이블: 상태 정의를 말로 먼저 (계단 → 0/1 배낭)

> 백로그 6번 — [기출 카운팅 DP](binary-distinct-combinations.md)와 다른 축: 저긴 "종류 세기", 여긴 **"최적값 표 채우기"**.
> **난이도**: 프로그래머스 **Lv2~3** · 기업 2번(중~중상).
> 진행: **🤔 생각 → 📖 읽기 → ✅ 확인** 순서.

---

## 0단계. 판별 — 지문 신호

| 지문 신호 | 판단 |
|---|---|
| "최대/최소 가치" + **선택이 자원(용량·기회)을 소모** | DP ⭕ — [그리디 드릴](greedy-exchange-argument.md)의 실패 신호가 곧 DP 신호 |
| "i번째까지 고려했을 때 ~"라는 서술이 자연스럽다 | DP ⭕ |
| 같은 부분 문제가 반복 계산될 것 같다 | DP ⭕ |
| 미래 선택이 과거와 무관 (자원 소모 없음) | 그리디로 충분 |

> **DP의 절반은 상태 정의를 한국어 한 문장으로 쓰는 것이다.** 문장이 안 써지면 코드도 못 쓴다 — 로드맵 D13의 "dp[i] 정의를 말로 먼저" 원칙의 실전판.

## 1단계. 🤔 생각 — 도입: 계단 오르기로 틀 잡기

*(한 번에 1칸 또는 2칸. n칸 오르는 방법 수. dp[i]를 한 문장으로 정의해 보라.)*

<details><summary>📖 추론 열기</summary>

**정의**: `dp[i] = "i번째 칸에 도달하는 방법의 수"`. 마지막 걸음은 1칸이었거나 2칸이었거나 둘뿐이고 겹치지 않으므로 —

```
dp[i] = dp[i-1] + dp[i-2]      (마지막 걸음으로 분류 — 빠짐없이, 겹침없이)
```

> **"마지막 행동으로 분류"**가 점화식 유도의 만능 손잡이다. [카운팅 DP 기출](binary-distinct-combinations.md)도 "마지막 글자로 분류"였다 — 같은 손, 다른 문제.

</details>

**✅ 확인**: dp[1]=1, dp[2]=2, dp[3]=3, dp[4]=5 — 피보나치. n=3을 직접 나열(1+1+1, 1+2, 2+1)해서 3 확인.

## 2단계. 🤔 생각 — 본체: 0/1 배낭. 상태에 왜 차원이 하나 더 붙나?

*(무게 w[i]·가치 v[i]인 물건들, 용량 C 배낭, 가치 최대화. dp[i]만으로 안 되는 이유는?)*

<details><summary>📖 추론 열기</summary>

"i번째까지의 최대 가치"만 알면 **남은 용량을 모르기 때문에** 다음 물건을 넣을 수 있는지 판단 불가. 미래 판단에 필요한 정보가 상태에 다 들어가야 한다:

**정의**: `dp[i][c] = "앞의 i개 물건만 고려하고, 용량 c를 쓸 수 있을 때의 최대 가치"`

마지막 행동(i번째 물건)으로 분류하면 — 안 넣는다 / 넣는다:

```
dp[i][c] = max( dp[i-1][c],                    // i번째를 안 넣음
                dp[i-1][c - w[i]] + v[i] )     // 넣음 (c >= w[i]일 때만)
```

> **상태 설계 원칙**: "이 시점 이후의 결정에 영향을 주는 과거 정보"가 전부 상태에 들어가야 한다 — 격자 탐색에서 (위치+열쇠)로 방문 차원을 늘리던 것과 같은 원리다.

</details>

**✅ 확인**: 점화식의 두 갈래가 "빠짐없이·겹침없이"인지 — i번째 물건의 운명은 넣거나 안 넣거나 둘뿐 ✓

## 3단계. 결론 — 코드: 1차원 압축 + **역순의 이유** (Java)

`dp[i][*]`는 `dp[i-1][*]`만 참조하므로 1차원으로 압축되는데, **순회 방향이 정답의 갈림길**이다:

```java
static int knapsack(int C, int[] w, int[] v) {
    int[] dp = new int[C + 1];                    // dp[c] = 용량 c의 최대 가치
    for (int i = 0; i < w.length; i++)
        for (int c = C; c >= w[i]; c--)           // ★ 역순! 이유는 아래
            dp[c] = Math.max(dp[c], dp[c - w[i]] + v[i]);
    return dp[C];
}
```

**왜 역순인가**: `dp[c - w[i]]`는 **이전 물건까지의 값(i-1 행)**이어야 한다. 정순으로 돌면 방금 이번 물건으로 갱신한 값을 다시 읽어 — **같은 물건을 여러 번 넣는 셈**이 된다. (뒤집어 말하면: **물건을 무한정 넣을 수 있는 "완전 배낭"은 일부러 정순으로 돈다** — 방향 하나가 문제 종류를 가른다.)

## 4단계. ✅ 전체 확인 — C=5, 물건 (w,v) = (2,3), (3,4), (4,5)

| 처리 후 | dp[0..5] |
|---|---|
| 초기 | 0 0 0 0 0 0 |
| (2,3) | 0 0 3 3 3 3 |
| (3,4) | 0 0 3 4 4 **7** |
| (4,5) | 0 0 3 4 5 7 |

**답: dp[5] = 7** ((2,3)+(3,4) = 무게 5, 가치 7 ✓ — (4,5) 단독 5보다 큼)

## 5단계. 함정 체크리스트

- [ ] **0/1 배낭 = 역순, 완전 배낭 = 정순** — 방향 실수가 곧 다른 문제의 답
- [ ] 상태 정의 문장을 주석으로 코드 위에 먼저 쓰기 — 디버깅의 기준점
- [ ] dp 배열 크기 `C+1` (용량 0 포함), 초기값이 0인 게 맞는 문제인지 (불가능 상태를 −∞로 둬야 하는 변형)
- [ ] 가치 합이 int를 넘는 입력 규모면 long
- [ ] "방법의 수"를 물으면 max 대신 **덧셈** — 최적화 DP와 카운팅 DP의 갈림 ([기출](binary-distinct-combinations.md))

## 3단 요약 (암기)

- **① 결론 · WHAT** — 테이블 DP는 ① 상태를 한국어 한 문장으로 정의 ② **마지막 행동으로 분류**해 점화식 ③ 참조 방향에 맞는 순회 — 의 3단계다. 배낭은 `dp[c] = max(안 넣음, dp[c−w]+v)`에 **역순 순회**.
- **② 원리 · HOW** — 상태에는 "미래 결정에 필요한 과거 정보 전부"가 들어가야 한다(그래서 배낭엔 용량 차원 추가). 역순의 이유는 1차원 압축에서 `dp[c−w]`가 이전 행 값으로 남아 있어야 하기 때문 — 정순은 같은 물건 중복 사용(=완전 배낭)이 된다.
- **③ 확장 · TRADE-OFF** — 그리디 실패 신호(선택이 자원 소모)가 곧 DP 신호다. 같은 틀에서 LIS(상태=끝 원소), 편집 거리(2차원 문자열)로 확장되고, 상태 공간이 너무 크면(10⁹ 용량) DP가 아니라 [파라메트릭 이분탐색](parametric-binary-search.md)이나 그리디 재검토 신호다 — 상태 크기 견적이 판별의 마지막 관문.
