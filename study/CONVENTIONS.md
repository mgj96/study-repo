# study 폴더 표준 형식 — 책 구조

> 목적: 노트를 **한 권의 책**으로 읽고 듣게 한다. 주제: "구조를 설계하고, 운영 중에 바꾸는 엔지니어".
> 2026-11 재편: 주제별 `concept.md + qna.md + deep-*.md` 구조를 **장(chapter) 단위 한 파일**로 합쳤다.

---

## 1. 표준 형식 — 장 하나 = 파일 하나

```
study/book/
├─ preface/00-how-to-read.md        서문
├─ part1/ ch01 ~ ch04               1부 컴퓨터가 일하는 방식
├─ part2/ ch05 ~ ch09               2부 데이터와 일관성
├─ part3/ ch10 ~ ch13               3부 경계를 긋는 법
├─ part4/ ch14 ~ ch15               4부 운영 중인 구조 바꾸기
├─ part5/ ch16 ~ ch17               5부 AI 시대의 검증
└─ appendix/ a1 ~ e4                부록 A 언어·도구 / B 수학 / C AI·ML / D 그래픽스·Unity / E 면접·코테
```

- 파일 이름: `chNN-주제.md`, 길면 절로 나눠 `chNN-M-주제.md` (2.1, 2.2 …). 부록은 `a1-…`, `c3-…`.
- **절로 나누는 기준**: 귀로 한 번에 듣기 좋은 분량(약 20~30분, 대략 40KB 이하). 넘으면 절로 쪼갠다.

### 장(절) 뼈대
```
# N장 제목  (절이면: N장 제목 · N.M 절 제목)
> M부 부 제목
## 들어가며          ← 이 장이 왜 필요한지, 앞 장과 어떻게 이어지는지 (듣기용이라 필수)
---
## 본문 섹션들        ← 개념 → 심화 순서. 섹션 끝에 핵심 요약·참조
## 정리 Q&A          ← 있으면 장 끝에. 3단(① 결론·WHAT / ② 원리·HOW / ③ 확장·TRADE-OFF)
## 다음으로          ← 다음 장이 왜 이어지는지 한두 문장 + 👉 다음 장 링크
```

### 새 글을 쓸 때
- **새 장/절**: `study/book/partN/`에 파일을 만들고 `site/sidebar.mjs`에 한 줄 추가. 순서가 곧 이전/다음 순서다. 부 합본에 넣으려면 `parts`의 `files`에도 추가.
- **기존 장 보강**: 새 파일을 만들지 말고 해당 장 안에 섹션으로 넣는다. 너무 길어지면 절로 나눈다.
- 듣기용: 각 페이지 위 **원문 링크 복사** 버튼(raw 주소), 부 합본은 `https://mgj96.github.io/study-repo/bundle/<part1~5|appendix>.md`.

## 1.5 작성 원칙 (내용 스타일) ⭐

1. **쉽게 쓴다 (12살 눈높이)** — 어려운 용어는 비유·한 줄 뜻풀이와 함께. 먼저 "쉬운 그림" → 그다음 정확한 용어.
2. **얕게 시작, 점진적 딥다이브** — 한 번에 다 쓰지 않는다. 각 주제는 **핵심만 약간** 먼저 → 사용자가 물어보면 그 부분을 더 깊이 파고든다. (심화는 "더 볼까요?" 식으로 이어가기)
3. **Q&A 3단 고정** — `① 결론·WHAT / ② 원리·HOW / ③ 확장·TRADE-OFF`.
4. **상호 링크** — 관련 개념(예: 박싱↔GC, 값/참조 타입)은 서로 연결.

> 즉, 문서는 "두껍게 다 채운 교과서"가 아니라 **"쉬운 뼈대 + 점점 깊어지는 층"**. 깊이는 대화로 쌓는다.

> ✍️ **글 쓰는 법(기억에 남고 흐름 좋게)은 [writing-guide.md](writing-guide.md) 참고** — SUCCESs·7단계 템플릿·체크리스트.

### 중요도 기반 깊이 + 도식/NotebookLM 규칙 ⭐
- **중요도 판단**: 처음 보는 사용자에게 **핵심 개념**은 장면·비유·도식으로 **상세히**, **부수적·단순 개념**은 짧게. (모두를 똑같이 길게 쓰지 않는다)
- **개념 단위로**: 입문자가 계단 밟듯 한 개념씩.
- **같은 md 하나로 사이트 + NotebookLM 둘 다 커버**. 상세 서술은 양쪽 다 이득.
- **도식엔 반드시 텍스트 설명 동반**: Mermaid는 NotebookLM에서 그림이 안 보이므로, 도식 바로 아래(또는 위)에 그 내용을 **한두 문장 글로** 풀어 적는다. (그림 없이도 뜻이 통하게 = 접근성 + NotebookLM 캡처)

### 심화(딥다이브) 정리 원칙 ⭐
딥다이브를 요청받으면 얕은 뼈대와 달리 **깊고 길게, 근거를 붙여** 정리한다.
- **웹검색 + 논문**에서 찾아 **핵심을 발췌·인용**하고 출처(저자·연도·URL/arXiv)를 단다.
- **길이 제한 없음** — 몇십 장이 넘어가도 된다. 대신 12살 눈높이 요약 → 정확한 심화 순서를 지킨다.
- 저작권: 원문 긴 인용은 피하고 짧은 발췌 + 내 말로 재정리 + 출처 링크.
- 심화 결과물은 관련 장 안에 섹션으로 넣는다. 길어지면 그 장을 절(N.M)로 나눈다.

## 1.6 사이트 렌더링 규칙 ⚠️

사이트는 Meta Astryx의 Markdown 컴포넌트로 렌더링된다. 이 컴포넌트는 **HTML 태그를 그리지 않는다.** 그래서 마크다운 본문에서 다음을 지킨다:
- **HTML 태그를 쓰지 않는다.** 예외는 `<details><summary>제목</summary> … </details>` 접기 하나뿐이다(빌드 때 접기 블록으로 바뀐다).
- **꺾쇠(`<`)는 항상 백틱/코드로**: 제네릭·부등호는 `` `List<Integer>` ``, `` `O(1) < O(n)` `` 처럼. 태그로 오해받지 않게 하는 습관이다.
- **수식은 `$...$`(인라인) / `$$...$$`(블록) LaTeX** 사용 (KaTeX/MathJax 렌더). 예: `$\text{Attention}(Q,K,V)=\text{softmax}(QK^\top/\sqrt{d_k})V$`.
- **가격 등 단독 `$`** 는 `\$`로 이스케이프(수식으로 오인 방지).
- ASCII 다이어그램·의사코드는 그대로 ```코드블록``` 유지.

## 1.7 사이드바 = 목차

- 사이드바는 책 목차 그 자체다. 모든 장·절을 순서대로 넣는다.
- 이전/다음 링크는 사이드바 순서를 따르며, 책(`/book/`) 페이지끼리만 이어진다.
- 아주 작은 보충은 새 페이지 대신 같은 문서 안 **`<details>` 접기 블록**으로:
  ```
  <details><summary>더 깊이: ○○</summary>

  내용...

  </details>
  ```
